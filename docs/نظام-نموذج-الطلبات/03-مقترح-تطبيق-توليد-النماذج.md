## الفكرة الأساسية

بدلاً من أن يُنشئ كل مستخدم النموذج وكود Apps Script يدوياً من الصفر كل مرة، نبني **تطبيق ويب داخلي** يقوم بما يلي تلقائياً:

1. **يستورد** ملف Excel (القالب الخاص بالمستخدم)
2. **يقرأ** أسماء الأعمدة ويستنتج حقول النموذج منها
3. **يعرض** واجهة لتخصيص كل حقل (نوعه، هل هو إلزامي، قائمة منسدلة...؟)
4. **يُولّد** تلقائياً:
   - ملف `form.html` الاحترافي الجاهز للاستضافة
   - كود `Code.gs + Email.gs + Helpers.gs` الجاهز للنسخ
   - تعليمات الإعداد خطوة بخطوة مُخصَّصة للمشروع
5. **يتيح** تحميل كل شيء دفعة واحدة

### 1. معالجة ملف Excel — المدخل الرئيسي

**التوصية:** استخدم مكتبة `xlsx` (SheetJS) في JavaScript لقراءة الملف من جانب العميل (browser) دون أي سيرفر.

**المزايا:**
- لا تحميل للملف لأي خادم خارجي = أمان تام
- يعمل بالكامل في المتصفح
- سريع جداً حتى مع ملفات كبيرة

**المنطق المقترح لقراءة الأعمدة:**

```javascript
// عند رفع الملف
fileInput.addEventListener('change', async (e) => {
  const file = e.target.files[0];
  const buffer = await file.arrayBuffer();
  const wb = XLSX.read(buffer, { type: 'array' });

  // قراءة أول ورقة
  const sheetName = wb.SheetNames[0];
  const ws = wb.Sheets[sheetName];

  // استخراج أسماء الأعمدة من الصف الأول
  const range = XLSX.utils.decode_range(ws['!ref']);
  const headers = [];
  for (let col = range.s.c; col <= range.e.c; col++) {
    const cell = ws[XLSX.utils.encode_cell({ r: 0, c: col })];
    if (cell && cell.v) {
      headers.push({
        excelCol : XLSX.utils.encode_col(col), // A, B, C...
        arabicName: cell.v,                     // الاسم العربي
        type     : guessFieldType(cell.v),      // تخمين ذكي للنوع
        required : true,
        placeholder: '',
        options  : [],                           // للقوائم المنسدلة
      });
    }
  }
  renderFieldEditor(headers);
});

// تخمين ذكي لنوع الحقل من اسمه العربي
function guessFieldType(name) {
  if (/هاتف|موبايل|جوال|تلفون/.test(name)) return 'tel';
  if (/بريد|إيميل|ايميل|email/.test(name)) return 'email';
  if (/تاريخ|يوم/.test(name)) return 'date';
  if (/عمر|رقم|عدد|مبلغ/.test(name)) return 'number';
  if (/ملاحظ|تفاصيل|وصف|شرح|اقتراح|شكوى/.test(name)) return 'textarea';
  if (/نوع|جنس|فئة|تصنيف|حالة|مستوى/.test(name)) return 'select';
  return 'text';
}
```

**توصية إضافية:** إذا كان الملف يحتوي بيانات في الصفوف (ليس فارغاً تماماً)، استخدم أول صف بيانات لتخمين نوع الحقل من القيم الموجودة.

### 2. محرر الحقول — القلب التفاعلي للتطبيق

**التوصية:** بعد قراءة الأعمدة، اعرض للمستخدم جدولاً تفاعلياً يمكّنه من تخصيص كل عمود:

| الخيار | الوصف | التنفيذ |
|--------|-------|---------|
| **اسم الحقل** | الاسم الظاهر في النموذج | input text قابل للتعديل |
| **نوع الحقل** | نص / هاتف / بريد / تاريخ / قائمة / نص طويل | select |
| **إلزامي؟** | checkbox | checkbox |
| **مساعد (placeholder)** | النص الرمادي داخل الحقل | input text |
| **خيارات القائمة** | إن كان نوعه "قائمة منسدلة" | textarea قابل للفصل بفاصلة |
| **تحقق خاص** | رقم هاتف سوري / عراقي / إلخ | select |
| **مخفي من النموذج** | عمود يُملأ تلقائياً (التاريخ، رقم الطلب) | checkbox |

**حقول يُنصح بإضافتها تلقائياً بغض النظر عن الملف:**
```
✅ رقم الطلب     — يُولَّد تلقائياً، لا يراه المستخدم
✅ تاريخ الإرسال — تلقائي
✅ وقت الإرسال   — تلقائي
✅ الحالة         — قائمة منسدلة (جديد / قيد المعالجة / مكتمل)
```

### 3. مولّد النموذج — أهم قرار تصميمي

**التوصية الذهبية:** لا تنشئ نموذجاً ذا خطوة واحدة (صفحة طويلة). استخدم **نموذج متعدد الخطوات (Multi-step Wizard)** دائماً لهذه الأسباب:

| السبب | التأثير |
|-------|---------|
| معدل الإكمال يرتفع 40-60% | المستخدمون لا يشعرون بالإرهاق |
| تحقق تدريجي | الأخطاء تُكتشَف مبكراً |
| صفحة مراجعة نهائية | تقليل الأخطاء قبل الإرسال |
| يناسب الموبايل تماماً | كل خطوة تناسب الشاشة الصغيرة |

**خوارزمية التقسيم التلقائي للخطوات:**

```javascript
function distributeFieldsIntoSteps(fields) {
  const steps = [];
  const FIELDS_PER_STEP = 4; // الحد الأمثل: 3-5 حقول في كل خطوة

  // الحقول الشخصية دائماً في الخطوة الأولى
  const personalTypes = ['text', 'tel', 'email'];
  const personal = fields.filter(f => personalTypes.includes(f.type)
                               && !f.hidden);
  const details  = fields.filter(f => !personalTypes.includes(f.type)
                               && !f.hidden);

  if (personal.length > 0) steps.push({ title: 'بياناتك الشخصية', fields: personal });
  if (details.length > 0)  steps.push({ title: 'تفاصيل طلبك',    fields: details  });

  // الخطوة الأخيرة دائماً: مراجعة وإرسال
  steps.push({ title: 'مراجعة وإرسال', fields: [], isReview: true });
  return steps;
}
```

### 4. التحقق من الحقول — القواعد الاحترافية

// قاموس قواعد التحقق الجاهزة
const VALIDATION_RULES = {
  text    : (v, min=2, max=200) => v.trim().length >= min && v.trim().length <= max,
  tel     : (v) => /^[0-9+\s\-\(\)]{7,15}$/.test(v.trim()),
  email   : (v) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v.trim()),
  number  : (v, min=0, max=Infinity) => !isNaN(v) && +v >= min && +v <= max,
  date    : (v) => !isNaN(Date.parse(v)),

  select  : (v, options) => options.includes(v),

  syrianPhone : (v) => /^(09[0-9]{8}|(\+963)[0-9]{9})$/.test(v.replace(/\s/g,'')),

### 6. قوالب البريد الإلكتروني — التوصيات الاحترافية

**التوصية الكبرى:** لا تستخدم قالباً واحداً لكل الجهات. وفّر **3 أنماط مختلفة**:

#### النمط الأول: المؤسسي (Corporate)
- خلفية بيضاء + شريط رأس ملوّن
- جدول بيانات منظّم
- زر CTA واحد واضح "عرض الجدول"
- مناسب لـ: الشركات، الجهات الحكومية

#### النمط الثاني: الدافئ (Friendly)
- أيقونات كبيرة + ألوان دافئة
- رسالة شخصية بالاسم
- مناسب لـ: الجمعيات، المنظمات غير الربحية

#### النمط الثالث: البسيط (Minimal)
- نص احترافي مباشر بدون صور
- يصل حتى في أضعف الاتصالات
- لا يقع في Spam
- مناسب لـ: الجهات التي تتلقى آلاف الطلبات يومياً

**قاعدة Subject Line الاحترافية:**

```javascript
// ❌ سيء — مملّ وعام
"طلب جديد"

// ❌ سيء — كثير رموز = Spam
"🔴🔴🔴 طلب عاجل جداً 🔴🔴🔴"

// ✅ احترافي — معلومة + رقم + تصنيف
`[${orgName}] طلب #${requestNumber} — ${requestType} (جديد)`

// ✅ احترافي مع الأولوية
`⚡ عاجل | طلب #${requestNumber} — ${requestType} | ${orgName}`
`📋 طلب جديد #${requestNumber} — ${requestType} | ${orgName}`
`✅ تأكيد استلام طلبك #${requestNumber} — ${orgName}`
```

**توصية للـ HTML Email:**
- دائماً أضف `<meta name="viewport">` لدعم الموبايل
- استخدم **Inline CSS فقط** — معظم عملاء البريد يتجاهلون `<style>`
- اختبر على Gmail + Outlook + Apple Mail (تختلف كثيراً)
- الحجم الأقصى المقبول: 102 KB (Gmail يقطع ما فوقه)
- لا تستخدم JavaScript في البريد (يُحذَف دائماً)
- اختبر على Litmus أو Email on Acid قبل الإطلاق

### 7. استضافة النموذج على Google Sites — الدليل الاحترافي

**المشكلة الحقيقية:** Google Sites لا يسمح بكود JavaScript تفاعلي معقد مباشرة.

**الحل الاحترافي الصحيح: Google Sites + Embed HTML**

```
الطريقة الصحيحة:
1. إنشاء موقع Google Sites
2. إضافة قسم "تضمين" (Embed)
3. اختيار "تضمين URL" وليس "تضمين كود"
4. رفع form.html على:
   - GitHub Pages (مجاني) ← الأفضل
   - Netlify Drop (مجاني)
   - Google Drive (محدودية في JavaScript)
5. الصق رابط صفحة HTML في Google Sites
```

**لماذا ليس مباشرة؟**
Google Sites يفلتر جزءاً من JavaScript للأمان. الحل: استضف HTML كملف مستقل ثم ضمّنه كـ iframe.

**البدائل الاحترافية للاستضافة المجانية:**

| الخدمة | المميزات | المحدودية |
|--------|---------|----------|
| **GitHub Pages** | مجاني، موثوق، نطاق `.github.io` | يحتاج حساب GitHub |
| **Netlify** | مجاني، سحب وإفلات، HTTPS تلقائي | 100 GB/شهر |
| **Cloudflare Pages** | مجاني، CDN عالمي | يحتاج حساب |
| **Vercel** | مجاني، سريع جداً | للمطوّرين |
| **Google Sites Embed** | ضمن نظام Google | JavaScript محدود |

**التوصية:** استخدم **Netlify Drop** — اسحب الملف وأفلته، يعمل فوراً، HTTPS مجاني.

### 8. تعليمات نشر Apps Script — الأخطاء الشائعة وتجنّبها

**الخطأ الشائع #1: نسيان قبول الأذونات**
```
الحل: عند أول نشر، شغّل دالة testConnection() أولاً
قبل نشر Web App — هذا يُجبرك على قبول الأذونات مرة واحدة.
بعدها، الـ Web App يعمل بدون أي تدخل.
```

**الخطأ الشائع #2: تعديل الكود بدون نشر جديد**
```
عدّلت الكود → لكن الـ Web App لا يزال يعمل بالكود القديم
الحل: كل تعديل يستلزم نشراً جديداً (ليس تعديل النشر القائم)
```

**الخطأ الشائع #3: CORS وno-cors**
```
Apps Script لا يرسل CORS headers للخارج
الحل الوحيد: استخدم mode:'no-cors' في fetch
العيب: لا تستطيع قراءة الرد → استخدم رقم طلب مؤقت من جانب العميل
أو: استخدم JSONP (قديم) أو Apps Script Proxy (معقد)
```

**الخطأ الشائع #4: حصة 100 إيميل/يوم**
```
Gmail العادي = 100 إيميل/يوم
طلبان = إيميلان (للمسؤول + للمستخدم) = فعلياً 50 طلب/يوم
الحل: استخدم Workspace ($6/شهر) أو أوقف إيميل المستخدم لغير المهم
أو: استخدم Resend.com API (مجاني حتى 3,000/شهر)
```

**الخطأ الشائع #5: timezone خاطئ**
```
Apps Script يعمل على GMT افتراضياً
الحل: دائماً مرّر timezone صريح لكل Utilities.formatDate()
مثال: Utilities.formatDate(now, 'Asia/Damascus', 'yyyy/MM/dd')
```

### Stack التقنية المقترحة للتطبيق

| المكوّن | التقنية | السبب |
|---------|--------|-------|
| **الواجهة** | React + Vite | سريع، تفاعلي، مناسب للـ state المعقد |
| **قراءة Excel** | SheetJS (xlsx) | الأفضل عالمياً، يعمل في المتصفح |
| **المحرر التفاعلي** | React DnD / dnd-kit | سحب وإفلات لإعادة ترتيب الحقول |
| **المعاينة** | iframe sandbox | عزل تام للنموذج |
| **تحميل ZIP** | JSZip + FileSaver | توليد ZIP في المتصفح |
| **التنسيق** | Tailwind CSS | سريع وخفيف |
| **الحالة** | Zustand أو Jotai | أبسط من Redux لهذا النوع |
| **توليد PDF** | jsPDF أو html2canvas | لتعليمات الإعداد |
| **لا سيرفر** | كل شيء في المتصفح | أمان + سرعة + لا تكلفة |

  const project = {

    orgName   : config.orgName,
    adminEmail: config.adminEmail,
    fields    : config.fields,
    template  : config.emailTemplate,

}

// استعادة مشروع محفوظ
async function loadProject(file) {

## سادساً: توصياتي الشخصية كخبير

---

### ✅ افعل دائماً

1. **اختبر على الموبايل أولاً** — 70%+ من المستخدمين العرب يستخدمون الهاتف
2. **أضف Autosave** — احفظ البيانات في localStorage كل 30 ثانية لمنع فقدان البيانات
3. **أضف مؤشر تقدم** — شريط يُظهر للمستخدم في أي خطوة هو
4. **اختبر الإرسال بدون إنترنت** — أظهر رسالة خطأ واضحة لا تجمّد الصفحة
5. **وثّق كل تغيير** — كل إصدار من Apps Script له وصف واضح
6. **أضف حقل "طريقة التواصل المفضّلة"** — هاتف / واتساب / بريد (يُحسّن تجربة المستخدم)
7. **استخدم أرقام طلبات قابلة للتذكر** — مثل REQ-2605-0047 (سنة + شهر + تسلسل)

### ❌ تجنّب دائماً

1. **لا تطلب معلومات أكثر من اللازم** — كل حقل إضافي يقلّل معدل الإكمال 5-10%
2. **لا تستخدم CAPTCHA مرئي** — يُنفّر المستخدمين، استخدم Honeypot بدلاً
3. **لا تُرسل إيميلاً بدون رقم مرجعي** — المستخدم لن يتذكر تفاصيله
4. **لا تجعل خطأ الإرسال مبهماً** — "حدث خطأ" لا تكفي، وضّح السبب وما يفعله المستخدم
5. **لا تثق بالبيانات من العميل وحده** — دائماً تحقق جانب الخادم (Apps Script)
6. **لا تضع معرّف الجدول في كود النموذج** — هو في الـ Backend فقط

## الخلاصة

هذا التطبيق سيحوّل عملية بناء نموذج الطلبات من **مهمة تقنية تأخذ 5-7 أيام** إلى **عملية تستغرق 15 دقيقة** لأي مستخدم غير تقني. القيمة الحقيقية ليست في الكود المُولَّد فقط، بل في:

- **تقليص الأخطاء** الناجمة عن الإعداد اليدوي
- **توحيد الجودة** عبر كل المشاريع
- **تمكين غير التقنيين** من إنشاء نظام احترافي دون مساعدة
- **توفير الوقت** لكل جهة جديدة تريد اعتماد هذا النظام
