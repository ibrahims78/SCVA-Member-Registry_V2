## 1. نظرة عامة على المشروع

### 1.1 الهدف

بناء نظام متكامل لاستقبال طلبات الجمهور العام (أي جهة: مؤسسة، نقابة، جمعية، خدمة عملاء، ...) بحيث:

- يتعامل المستخدم مع **نموذج عربي احترافي** في المتصفح
- تُحفظ البيانات تلقائياً في **ملف Google Sheets عربي** قابل للتصدير كـ Excel
- يتلقى المسؤول **إشعاراً بريدياً فورياً** بتفاصيل الطلب
- يتلقى مقدّم الطلب **رسالة تأكيد احترافية** على بريده (إن أدخله)
- **كل شيء مجاني** — لا سيرفر، لا اشتراك، لا hosting مدفوع

### 1.2 مخطط تدفق العمل

```
المستخدم يفتح رابط النموذج
           ↓
يعبّئ بياناته ويضغط "إرسال"
           ↓
JavaScript يُرسل البيانات لـ Apps Script
           ↓
   ┌────────────────────┐
   │   Apps Script       │
   │   يُنفّذ 3 مهام     │
   └──────┬──────┬──────┘
          │      │      │
          ▼      ▼      ▼
     يكتب    يُرسل   يُرسل
   في Sheets  للمسؤول للمستخدم
          │      │      │
          ▼      ▼      ▼
    سجل البيانات  إشعار  تأكيد
     في Excel    فوري   الاستلام
```

### 1.3 المبدأ الأساسي

```
النموذج (HTML)  ─── fetch POST ───→  Apps Script Web App
                                            │
                              ┌─────────────┼─────────────┐
                              ▼             ▼             ▼
                        Google Sheets    Gmail         Gmail
                        (سجل البيانات) (للمسؤول)    (للمستخدم)
```

### 1.4 المزايا الأساسية

| الميزة | الوصف |
|--------|-------|
| **مجاني بالكامل** | لا hosting، لا domain، لا قاعدة بيانات مدفوعة |
| **عربي بالكامل** | النموذج والجدول والإشعارات باللغة العربية |
| **لا سيرفر** | Google تتولى كل شيء (Apps Script + Sheets) |
| **موثوقية عالية** | بنية تحتية Google (99.9% uptime) |
| **سهولة الاستخدام** | الفريق يعمل على Sheets المألوف |
| **قابل للتصدير** | كل البيانات تُصدَّر كـ Excel في أي وقت |
| **إشعارات فورية** | المسؤول يُبلَّغ فور وصول أي طلب |

## 3. البنية التقنية الكاملة

### 3.1 شرح كل طبقة

#### الطبقة الأولى: النموذج (Frontend)
- ملف HTML واحد يضم كل شيء (HTML + CSS + JavaScript)
- لا framework، لا مكتبات خارجية — يعمل في أي متصفح
- يُستضاف على **Google Sites** (مجاني، ضمن حساب Google)
- موجَّه بالكامل للغة العربية (RTL)
- نموذج من 3 خطوات: البيانات الشخصية ← تفاصيل الطلب ← المراجعة والإرسال

#### الطبقة الثانية: Apps Script (Backend)
- كود JavaScript يعمل مباشرة على خوادم Google
- يستقبل الطلبات كـ Web App (مثل API endpoint)
- يكتب في Sheets، يُرسل البريد، يُرجع استجابة JSON
- لا سيرفر، لا استضافة، Google تتولى كل شيء

#### الطبقة الثالثة: Google Sheets (Database)
- جدول بيانات بـ **12 عمود عربي** محدد مسبقاً
- كل إرسال يُضيف صفاً جديداً تلقائياً
- يمكن تصديره كـ Excel .xlsx في أي وقت
- مشاركة مع الفريق بضغطة واحدة

### 3.2 تدفق البيانات التفصيلي

```
[1]  المستخدم يضغط "إرسال"
         ↓
[2]  JavaScript يتحقق من صحة البيانات محلياً
         ↓
[3]  fetch POST → Apps Script Web App
         ↓
[4]  Apps Script يستقبل الطلب (doPost)
         ↓
[5]  التحقق من صحة البيانات جانب الخادم
         ↓
[6]  توليد رقم طلب فريد: REQ-YYYYMMDD-XXXX
         ↓
[7]  كتابة صف جديد في Google Sheets (12 خانة)
         ↓
[8]  إرسال إيميل HTML احترافي للمسؤول
         ↓
[9]  إرسال إيميل تأكيد للمستخدم (إن أدخل بريده)
         ↓
[10] إرجاع { status: 'success', requestNumber: 'REQ-...' }
         ↓
[11] النموذج يعرض صفحة تأكيد مع رقم الطلب
```

### 3.3 هيكل جدول البيانات (12 عمود عربي)

| عمود | الاسم العربي | المصدر |
|------|------------|--------|
| A | رقم الطلب | تلقائي (REQ-YYYYMMDD-XXXX) |
| B | تاريخ الإرسال | تلقائي |
| C | وقت الإرسال | تلقائي |
| D | الاسم الكامل | من مقدّم الطلب |
| E | رقم الهاتف | من مقدّم الطلب |
| F | البريد الإلكتروني | من مقدّم الطلب (اختياري) |
| G | المدينة / المنطقة | من مقدّم الطلب |
| H | نوع الطلب | من مقدّم الطلب (قائمة) |
| I | تفاصيل الطلب | من مقدّم الطلب |
| J | الحالة | افتراضي: جديد (يُحدَّث يدوياً) |
| K | ملاحظات المسؤول | يُعبّئه المسؤول |
| L | تاريخ آخر تحديث | تلقائي |

## 4. الأمان والحماية

### 4.1 طبقات الحماية المُطبَّقة

| الطبقة | الوصف | مكان التطبيق |
|--------|-------|-------------|
| **Honeypot** | حقل مخفي — البوتات تملؤه فيُهمَل الطلب | النموذج (HTML) |
| **فحص الوقت** | الإرسال في أقل من 3 ثوانٍ مشبوه | النموذج (JavaScript) |
| **تحقق جانب الخادم** | كل الحقول تُتحقَّق في Apps Script | Code.gs |
| **تنظيف HTML** | `escapeHtml()` يمنع XSS في قوالب البريد | Helpers.gs |
| **طول التفاصيل** | 10 أحرف كحدّ أدنى | كلا الجانبين |
| **تحقق البريد** | Regex على جانب الخادم | Apps Script |

### 4.2 ما يجب تجنّبه

```
❌ لا تضع معلومات طبية أو مالية حساسة جداً في هذا النظام
❌ لا تضع كلمات مرور أو أرقام هوية وطنية
❌ لا تضع معرّف الجدول (SPREADSHEET_ID) في كود النموذج العام
✅ كل الإعدادات الحساسة تبقى في Apps Script CONFIG فقط
✅ استخدم Script Properties للمفاتيح السرية (مثل مفتاح Gemini)
```

### 4.3 إعداد المتغيرات السرية بأمان

للإعدادات الحساسة مثل مفاتيح API الخارجية:
```
في Apps Script:
  مشروع → الإعدادات → خصائص البرنامج النصي
  أضف: GEMINI_API_KEY = مفتاحك_هنا
```

ثم في الكود اقرأها بأمان:
```javascript
const key = PropertiesService.getScriptProperties()
              .getProperty('GEMINI_API_KEY');
```

### 4.4 حماية إضافية اختيارية: reCAPTCHA v3

للمواقع ذات الحركة العالية أو المعرّضة للبوتات:
1. اذهب إلى: `google.com/recaptcha/admin`
2. أنشئ موقعاً → اختر **reCAPTCHA v3** (غير مرئي للمستخدم)
3. أضف المفتاح العام في النموذج
4. أضف المفتاح السري في Apps Script Properties
5. تحقق من نتيجة التحقق في `doPost()` قبل معالجة الطلب

## 6. دليل الصيانة والتشغيل

### 6.1 المهام اليومية (للمسؤول عن الطلبات)

```
✅ افتح Google Sheets وراجع الطلبات الجديدة (عمود J = "جديد")
✅ غيّر الحالة إلى "قيد المعالجة" عند البدء بالطلب
✅ أضف ملاحظاتك في عمود K "ملاحظات المسؤول"
✅ غيّر الحالة إلى "مكتمل" أو "مرفوض" عند الانتهاء
```

### 6.2 المهام الأسبوعية (للمسؤول التقني)

```
✅ افتح Apps Script → عرض → سجلات التنفيذ
✅ تحقق من عدم وجود أخطاء متكررة
✅ راقب عداد الإيميلات (هل اقترب من 100/يوم؟)
✅ صدّر نسخة xlsx احتياطية من Sheets:
   ملف → تنزيل → Microsoft Excel (.xlsx)
```

### 6.3 المهام الشهرية

```
✅ راجع إحصائيات الطلبات: الأكثر تكراراً، التوزيع الجغرافي
✅ افحص أداء Apps Script من لوحة التحكم
✅ راجع قائمة المشاركين في Sheets (أضف/أزل أعضاء الفريق)
✅ تأكد من صلاحية حساب Google وتحديث كلمة المرور إن لزم
```

### 6.4 تحديث الكود — قاعدة ذهبية مهمة

```
⚠️ كل تعديل في Apps Script يستوجب نشراً جديداً
   (تعديل النشر القديم لا يُطبَّق تلقائياً)

الخطوات:
1. عدّل الكود في محرر Apps Script
2. نشر → إدارة عمليات النشر → "نشر جديد"
3. أضف وصفاً: "الإصدار X.X — وصف التعديل"
4. اضغط "نشر"
5. إذا تغيّر الرابط → حدّثه في form.html أيضاً
6. وثّق التعديل في سجل التوثيق
```

### 6.5 النسخ الاحتياطي

| المكوّن | الوضع الافتراضي | الموصى به |
|---------|--------------|---------|
| Apps Script | مرفق تلقائياً بـ Drive | احتفظ بنسخة محلية من الكود |
| Google Sheets | محفوظ تلقائياً | نسخة xlsx أسبوعياً |
| form.html | لا نسخ تلقائي | احفظه على جهازك دائماً |

**تصدير تلقائي أسبوعي (اختياري):**
يمكن إضافة Trigger في Apps Script يُرسل ملف xlsx بالبريد تلقائياً كل أحد.

### 6.6 مشاركة الجدول مع الفريق

```
في Google Sheets:
اضغط "مشاركة" (Share) في الزاوية العلوية اليمنى
أضف بريد كل عضو مع تحديد الصلاحية:
  • محرر (Editor)  ← للمسؤولين الذين يُحدِّثون الحالات
  • معلّق (Commenter) ← للمراجعين
  • قارئ (Viewer) ← للمطلعين فقط
```

## 7. الأسئلة الشائعة والمشاكل المحتملة

### ❓ "الطلب وصل للجدول لكن البريد لم يصل"

**الأسباب المحتملة:**
1. `ADMIN_EMAIL` خاطئ في CONFIG
2. تجاوز حصة 100 إيميل/يوم
3. البريد وصل لمجلد Spam

**الحل:**
```
1. تحقق من CONFIG.ADMIN_EMAIL في Code.gs
2. افتح Apps Script → سجل التنفيذ → ابحث عن خطأ GmailApp
3. تحقق من مجلد Spam
4. شغّل دالة testConnection() من Apps Script للاختبار
```

---

### ❓ "الطلب لا يصل لـ Sheets ولا رسالة خطأ"

**الأسباب المحتملة:**
1. رابط Apps Script في HTML خاطئ أو قديم
2. `SPREADSHEET_ID` خاطئ في CONFIG
3. الـ Web App لم يُنشَر بصلاحية "أي شخص"

**الحل:**
```
1. تحقق من APPS_SCRIPT_URL في form.html
2. تحقق من CONFIG.SPREADSHEET_ID
3. تأكد من نشر جديد بصلاحية: Anyone
4. افتح Console المتصفح (F12) وابحث عن أخطاء fetch
```

---

### ❓ "الأحرف العربية تظهر مشوّهة في Sheets"

**الحل:**
```
تأكد من أن Apps Script يستخدم:
   JSON.parse(e.postData.contents)
وليس:
   e.postData.parameters

وتأكد أن ملف HTML محفوظ بترميز UTF-8
```

---

### ❓ "البريد يصل في Spam"

**الأسباب:**
- Gmail يصنّف رسائل Apps Script أحياناً كـ Spam
- خاصة إذا كانت الرسائل كثيرة أو تحوي روابط كثيرة

**الحلول (بالترتيب):**
```
1. أضف بريد الإرسال لجهات اتصالك (Contacts)
2. اجعل سطر الموضوع واضحاً بدون رموز مفرطة
3. استخدم Google Workspace للبريد المؤسسي ($6/شهر)
4. الخيار المتقدم: Resend.com (مجاني حتى 100/يوم)
```

---

### ❓ "كيف أُضيف حقلاً جديداً للنموذج؟"

```
الخطوات بالترتيب:
1. أضف عمود جديد في Sheets (مثال: عمود M "تاريخ الميلاد")
2. أضف الحقل في form.html مع التحقق المناسب
3. أضف الحقل في قسم المراجعة (review section)
4. في Code.gs، أضف الحقل في دالة writeToSheet():
   sheet.appendRow([..., data.birthDate, ...])
5. في Email.gs، أضف الحقل في قالب بريد المسؤول
6. أنشئ نشراً جديداً في Apps Script
```

---

### ❓ "كيف أُنشئ تقارير إحصائية؟"

```
في Google Sheets:
1. أضف ورقة جديدة اسمها "إحصائيات"
2. استخدم دالة COUNTIF:
   =COUNTIF('سجل الطلبات'!H:H, "شكوى")
3. استخدم COUNTA لعدد الطلبات الكلي:
   =COUNTA('سجل الطلبات'!A:A) - 1
4. أنشئ مخططاً بيانياً (Pie/Bar) من هذه الأرقام
5. الخيار الأفضل: اربطه بـ Looker Studio (مجاني)
   للحصول على لوحة تحكم احترافية وتفاعلية
```

---

### ❓ "كيف أُضيف تحليل ذكاء اصطناعي للطلبات؟"

يمكن ربط Gemini API مجاناً لتحليل كل طلب تلقائياً:
- تلخيص محتوى الطلب بجملة أو جملتين
- اقتراح أولوية المعالجة (عاجل / عادي / غير عاجل)
- تصنيف الطلب إذا كان النوع غير واضح

راجع **ملحق أ** في الجزء الثاني للكود الكامل.
