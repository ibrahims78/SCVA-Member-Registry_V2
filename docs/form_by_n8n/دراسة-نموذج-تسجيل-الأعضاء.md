## 1. نظرة عامة

### الهدف من المشروع
إنشاء نظام متكامل يُمكّن الجمعية القلبية السورية من مشاركة رابط نموذج احترافي مع الأعضاء لتعبئة بياناتهم بشكل مستقل، وإرسالها تلقائياً إلى ملفات الإكسل المخزّنة في البرنامج عبر مسار عمل آلي في n8n، مع التحقق من هوية المرسل وإشعار فوري لكل من المسؤول والعضو.

### المشكلة التي يحلّها
- حالياً تُدخَل بيانات الأعضاء يدوياً من قِبَل موظفي الجمعية
- العملية تستهلك وقتاً وتحتمل أخطاء في النقل
- لا توجد آلية لجمع البيانات مباشرة من الأعضاء أنفسهم
- لا توجد حماية تمنع التسجيلات العشوائية غير المرغوبة

### الحل المقترح
```
العضو ← يحصل على رمز الدعوة من الجمعية
    ↓
يفتح رابط النموذج ← يُدخل رمز التحقق ← يعبئ بياناته ← يضغط إرسال
    ↓
n8n يتحقق من الرمز ← يستقبل البيانات تلقائياً
    ↓
يُضيف البيانات إلى ملف الإكسل المناسب (حسب اللغة المختارة)
    ↓
يُرسل إشعاراً للمسؤول + رسالة تأكيد للعضو
```

## 3. نموذج الويب الخارجي

### 3.1 التصميم والهوية البصرية

النموذج ملف HTML واحد مكتفٍ بذاته (لا يحتاج سيرفر أو اتصال بالبرنامج) يتبع هوية SCVA البصرية تماماً:

- **نظام الألوان:** نفس التدرج الأزرق-الأخضر الداكن `(#0f2027 → #203a43 → #2c5364)`
- **الخطوط:** خط عربي واضح + خط إنجليزي متوافق
- **الشعار:** شعار SCVA واسم الجمعية في الأعلى
- **الظل والحواف:** نفس أسلوب البطاقات (cards) في البرنامج
- **الأزرار:** نفس تصميم الأزرار مع تأثيرات hover

### 3.2 شريط الأدوات العلوي

```
┌──────────────────────────────────────────────────────────┐
│  [شعار SCVA]  الجمعية القلبية السورية      [🌙] [AR|EN]  │
└──────────────────────────────────────────────────────────┘
```

- **زر الوضع الليلي/النهاري 🌙☀️:** يُبدّل بين الثيمين ويحفظ التفضيل في localStorage
- **زر اللغة [AR|EN]:** يُبدّل واجهة النموذج كاملاً مع دعم RTL/LTR الكامل

### 3.3 شريط التقدم (4 خطوات)

```
● ━━━━━━━━━ ○ ━━━━━━━━━ ○ ━━━━━━━━━ ○   25%
[التحقق]  [البيانات الأساسية]  [التواصل]  [المراجعة]
```

- الخطوة الأولى: إدخال رمز التحقق (شرط للمتابعة)
- الخطوة الثانية: البيانات الأساسية والمهنية
- الخطوة الثالثة: بيانات التواصل والعنوان
- الخطوة الرابعة: مراجعة كاملة قبل الإرسال

### 3.4 الحقول الإلزامية (★ نجمة حمراء)

هذه الحقول الخمسة إلزامية ولا يُقبل الإرسال بدونها:

| الرقم | الحقل بالعربية | الحقل بالإنجليزية | نوع الإدخال |
|-------|---------------|------------------|------------|
| 1 | **رمز التحقق ★** | **Verification Code ★** | نص (كود) |
| 2 | **الاسم الأول ★** | **First name ★** | نص |
| 3 | **الكنية ★** | **Last name ★** | نص |
| 4 | **الاسم الكامل بالعربية ★** | **Full name (Arabic) ★** | نص عربي |
| 5 | **الاسم الكامل بالإنجليزية ★** | **Full name (English) ★** | نص إنجليزي |

> تظهر النجمة ★ بالأحمر بجانب كل حقل إلزامي، ويظهر خط أحمر تحت الحقل عند محاولة المتابعة بدون ملئه.

### 3.7 صفحة التأكيد بعد الإرسال

بعد الإرسال الناجح تظهر صفحة تأكيد كاملة داخل النموذج تحتوي على:
- ✅ أيقونة نجاح متحركة (animation)
- رسالة شكر باسم العضو: "شكراً، محمد! تم استلام بياناتك بنجاح"
- ملخص البيانات المُرسَلة قابل للطباعة
- تنبيه: "إذا أدخلت بريدك، ستصلك رسالة تأكيد قريباً"
- زر "تسجيل عضو آخر" لإعادة النموذج فارغاً
- زر "طباعة" لطباعة ملخص الطلب

## 4. نظام التحقق من المرسل

### 4.1 المنهجية المعتمدة — الجمع بين مستويين من التحقق

تم اعتماد نظام تحقق مزدوج يجمع بين **الرمز العام** و**الرموز الفريدة** لتحقيق توازن مثالي بين الأمان وسهولة الإدارة:

```
المستوى الأول  — رمز الدعوة العام (General Invitation Code)
المستوى الثاني — رمز فريد لكل عضو (Unique Member Code)    [للمستقبل]
```

---

### 4.2 المستوى الأول — رمز الدعوة العام

#### آلية العمل
- رمز واحد تُحدده الجمعية وتُغيّره متى أرادت (مثلاً: `SCVA-2026`)
- يُعطى هذا الرمز للأعضاء الجدد عند التواصل معهم
- يُدخله العضو في خانة "رمز التحقق" في الخطوة الأولى من النموذج
- n8n يتحقق من تطابقه مع الرمز المُدخَل في إعدادات البرنامج
- إذا كان خاطئاً → يُرفض الطلب فوراً مع رسالة واضحة

#### إدارة الرمز في البرنامج
- المسؤول يُعدّل الرمز من صفحة الإعدادات في أي وقت
- عند التغيير يُصبح الرمز القديم غير صالح فوراً
- يُنصح بتغييره دورياً (كل موسم أو دورة تسجيل)

#### مثال على واجهة النموذج

```
┌──────────────────────────────────────────────────────────┐
│  🔐 رمز التحقق ★                                         │
│  ┌────────────────────────────────────────────────────┐  │
│  │  أدخل رمز الدعوة الذي حصلت عليه من الجمعية        │  │
│  └────────────────────────────────────────────────────┘  │
│  💡 للحصول على رمز الدعوة تواصل مع إدارة الجمعية        │
└──────────────────────────────────────────────────────────┘
```

---

### 4.3 المستوى الثاني — رموز فريدة لكل عضو (للمرحلة المستقبلية)

#### آلية العمل
- كل عضو يحصل على رمز شخصي فريد (مثلاً: `SCVA-2026-00142`)
- يُنشأ الرمز من داخل البرنامج في صفحة الإعدادات أو قسم الأعضاء
- يُرسَل للعضو عبر البريد الإلكتروني أو يُعطى له يدوياً
- يمكن ضبطه ليُستخدَم **مرة واحدة فقط** (one-time use)
- يمكن إلغاء رمز عضو بعينه دون التأثير على الآخرين
- يُسجَّل في n8n أن هذا الرمز استُخدم لمنع التكرار

#### تركيب الرمز الفريد
```
SCVA - [السنة] - [رقم متسلسل 5 أرقام]
مثال: SCVA-2026-00142
```

#### المزايا الإضافية للرموز الفريدة
| الميزة | الوصف |
|--------|-------|
| تتبع الهوية | يعرف النظام من أرسل البيانات بالضبط |
| منع التكرار | لا يمكن استخدام نفس الرمز مرتين |
| إلغاء فردي | يمكن إلغاء رمز عضو دون تأثير على الآخرين |
| إحصائيات | تقرير بمن سجّل ومن لم يسجّل بعد |

---

### 4.4 تصرف النموذج عند الرمز الخاطئ

```
العضو يُدخل رمزاً خاطئاً → يضغط "التالي"
    ↓
تظهر رسالة حمراء فورية:
"رمز التحقق غير صحيح. يُرجى التواصل مع إدارة الجمعية."
    ↓
لا يمكن الانتقال للخطوة التالية
    ↓
بعد 3 محاولات فاشلة → رسالة تحذيرية مع رابط التواصل
```

## 6. مسار العمل في n8n

### 6.1 رسم مخطط الـ Workflow الكامل

```
┌──────────────────────────────────────────────────────────────┐
│                       n8n Workflow                           │
│                                                              │
│  [1. Webhook Trigger]                                        │
│       ↓ POST /scva-member-register                           │
│       ↓ { language, verificationCode, firstName, ... }       │
│                                                              │
│  [2. Code Node — Verify Code]                                │
│       ↓ هل رمز التحقق صحيح؟                                 │
│       ↓ yes                    ↓ no                          │
│                         [Respond — 401 Error]               │
│                                                              │
│  [3. Code Node — Validate & Format]                          │
│       ↓ تنظيف + timestamp + تحقق من الحقول الإلزامية         │
│                                                              │
│  [4. IF Node — Language Check]                               │
│       ↓ ar                            ↓ en                  │
│                                                              │
│  [5a. Read AR Excel]          [5b. Read EN Excel]            │
│       ↓                              ↓                      │
│  [6a. Append Row AR]          [6b. Append Row EN]            │
│       ↓                              ↓                      │
│  [7a. Write AR Excel]         [7b. Write EN Excel]           │
│       ↓                              ↓                      │
│            └──────── [8. Merge] ────────┘                   │
│                            ↓                                │
│            [9. Send Email — Admin Notification]              │
│                            ↓                                │
│            [10. IF — Member Email Exists?]                  │
│                 ↓ yes               ↓ no                    │
│         [11. Send Email          [Skip]                     │
│           Member Confirmation]                              │
│                 ↓                                           │
│         [12. Respond to Webhook — 200 Success]              │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 تفاصيل كل عقدة

| العقدة | النوع | الوظيفة |
|--------|-------|---------|
| **1. Webhook** | Webhook Trigger | يستقبل POST من النموذج |
| **2. Verify Code** | Code (JS) | يقارن `verificationCode` بالرمز المحفوظ في المتغيرات |
| **3. Format** | Code (JS) | تنظيف + timestamp + تحقق من الإلزامية |
| **4. IF Language** | IF | `{{ $json.language === 'ar' }}` |
| **5a/5b. Read** | Read/Write Files | قراءة الإكسل المناسب |
| **6a/6b. Append** | Spreadsheet File | إضافة صف جديد |
| **7a/7b. Write** | Read/Write Files | حفظ الملف المحدَّث |
| **8. Merge** | Merge | دمج المسارين |
| **9. Email Admin** | Send Email | إشعار المسؤول |
| **10. IF Email** | IF | `{{ $json.email !== '' }}` |
| **11. Email Member** | Send Email | تأكيد للعضو |
| **12. Respond** | Respond to Webhook | `{ status: "success" }` |

## 9. الميزات الاحترافية الإضافية

### 9.1 حفظ تلقائي (Auto-save)
- كل ما يكتبه المستخدم يُحفظ تلقائياً في `localStorage` كل 30 ثانية
- عند العودة للصفحة بعد إغلاقها: "وجدنا بياناتك السابقة — هل تريد استكمالها؟"
- زر لمسح البيانات المحفوظة وبدء جديد

### 9.2 الحماية من الإرسال المتكرر
- عند الضغط على إرسال: يتعطل الزر فوراً ويظهر مؤشر دوار
- لا يمكن إرسال النموذج مرتين لنفس الجلسة
- رسالة واضحة "جارٍ الإرسال... يرجى الانتظار"

### 9.3 التحقق الفوري من الإدخال (Live Validation)
- يظهر ✅ أو ❌ بجانب كل حقل عند الانتهاء من الكتابة
- رسائل خطأ واضحة بالعربية أو الإنجليزية حسب اللغة المختارة
- التحقق من صحة صيغة البريد الإلكتروني فورياً
- التحقق من أن الاسم بالعربية يحتوي حروفاً عربية فعلاً

### 9.4 صفحة المراجعة الكاملة (الخطوة الرابعة)
- قبل الإرسال يرى العضو ملخصاً كاملاً لكل بياناته
- زر "تعديل" بجانب كل قسم للرجوع وتعديله
- مربع تأكيد: "أؤكد أن البيانات المُدخَلة صحيحة"

### 9.5 معالجة الأخطاء وانقطاع الإنترنت
- رسالة حمراء واضحة مع سبب الخطأ
- البيانات لا تُمسح عند الفشل
- زر "إعادة المحاولة" واضح
- حفظ البيانات في localStorage للمحاولة لاحقاً

### 9.6 حماية من محاولات التحقق المتكررة
- بعد 3 محاولات فاشلة لرمز التحقق → تجميد النموذج 5 دقائق
- رسالة: "تجاوزت عدد المحاولات المسموح بها. يُرجى المحاولة بعد 5 دقائق."
- يُسجَّل عدد المحاولات في localStorage

## 14. خطوات التشغيل بعد التنفيذ

### في البرنامج (مرة واحدة):
1. الدخول على صفحة **الإعدادات**
2. الانتقال لقسم "إعدادات نموذج التسجيل الخارجي"
3. تعيين **رمز الدعوة العام** (مثلاً: `SCVA-2026`)
4. إدخال **بريد الإشعارات** لاستقبال التنبيهات
5. لصق **رابط Webhook** من n8n
6. الحفظ
7. نسخ **رابط النموذج** ومشاركته مع الأعضاء

### في n8n (مرة واحدة):
1. فتح n8n → **Import** → اختيار `scva-member-workflow.json`
2. تعديل متغيرات البيئة (SMTP، مسارات الإكسل، الرمز)
3. تفعيل الـ Workflow
4. نسخ رابط Webhook ولصقه في إعدادات البرنامج

### للأعضاء:
1. يستلمون رابط النموذج + رمز الدعوة من الجمعية
2. يفتحون الرابط في أي متصفح
3. يُدخلون رمز الدعوة ويعبئون بياناتهم
4. ✅ تم — البيانات محفوظة تلقائياً
