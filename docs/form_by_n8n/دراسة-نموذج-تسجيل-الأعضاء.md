## 1. نظرة عامة

### الهدف من المشروع
إنشاء نظام متكامل يُمكّن الجمعية القلبية السورية من مشاركة رابط نموذج احترافي مع الأعضاء لتعبئة بياناتهم بشكل مستقل، وإرسالها تلقائياً إلى ملفات الإكسل المخزّنة في التطبيق عبر مسار عمل آلي في n8n، مع تحليل ذكي بالذكاء الاصطناعي وإشعار فوري لكل من المسؤول والعضو.

### المشكلة التي يحلّها
- حالياً تُدخَل بيانات الأعضاء يدوياً من قِبَل موظفي الجمعية
- العملية تستهلك وقتاً وتحتمل أخطاء في النقل
- لا توجد آلية لجمع البيانات مباشرة من الأعضاء أنفسهم
- لا توجد حماية تمنع التسجيلات العشوائية غير المرغوبة

### الحل المنفَّذ
```
العضو ← يحصل على رمز الدعوة من الجمعية
    ↓
يفتح رابط النموذج ← يُدخل رمز التحقق ← يعبئ بياناته ← يضغط إرسال
    ↓
n8n: يتحقق من الرمز → يُنسّق البيانات → يستدعي AI (اختياري)
    ↓
يُرسل البيانات بـ HTTP إلى سيرفر SCVA → يُضيفها لملف الإكسل
    ↓
يُرسل إشعاراً احترافياً للمسؤول (مع تحليل AI)
    ↓
يُرسل رسالة تأكيد شخصية للعضو (مع ترحيب AI)
```

## 3. نموذج الويب الخارجي

### 3.1 التصميم والهوية البصرية

النموذج ملف HTML واحد مكتفٍ بذاته (لا يحتاج framework أو اتصال دائم بالتطبيق) يتبع هوية SCVA البصرية:

- **نظام الألوان:** تدرج أزرق-أخضر داكن `(#0f2027 → #203a43 → #2c5364)`
- **الخطوط:** Cairo (عربي) + Inter (إنجليزي) عبر Google Fonts
- **الشعار:** شعار SCVA واسم الجمعية في الأعلى
- **الأزرار:** تصميم موحّد مع تأثيرات hover

### 3.2 شريط التقدم (4 خطوات)

```
● ━━━━━━━━━ ○ ━━━━━━━━━ ○ ━━━━━━━━━ ○   25%
[التحقق]  [البيانات الأساسية]  [التواصل]  [المراجعة]
```

| الخطوة | المحتوى |
|--------|---------|
| 1 — التحقق | إدخال رمز الدعوة (شرط لا يمكن تجاوزه) |
| 2 — البيانات الأساسية | الاسم بالعربية والإنجليزية، الجنس، الميلاد، التخصص، العضوية |
| 3 — التواصل | البريد، الهاتف، المدينة، العمل، ESC ID، تاريخ الانضمام |
| 4 — المراجعة | ملخص كامل قابل للتعديل قبل الإرسال |

### 3.3 الحقول الإلزامية (★)

| الحقل بالعربية | الحقل بالإنجليزية | مفتاح JSON |
|---------------|------------------|-----------|
| الاسم الأول ★ | First name ★ | `firstName` |
| الكنية ★ | Last name ★ | `lastName` |
| الاسم الكامل بالعربية ★ | Full name (Arabic) ★ | `fullName` |
| الاسم الكامل بالإنجليزية ★ | Full name (English) ★ | `englishName` |

## 4. نظام التحقق من المرسل

### 4.1 رمز الدعوة العام

- رمز واحد تُحدده الجمعية من صفحة الإعدادات (مثلاً: `SCVA-2026`)
- يُعطى للأعضاء الجدد عند التواصل معهم
- عند تغييره يصبح القديم غير صالح فوراً — الـ Workflow يقرأ الرمز المحدَّث من كود التحقق الذي يُحقَن تلقائياً عند التحميل

### 4.2 آلية التحقق في n8n

```
العضو يُرسل النموذج بـ verificationCode: "SCVA-2026"
    ↓
عقدة Verify Invitation Code تُقارنه مع الرمز المُضمَّن في الكود
    ↓
تطابق ✅ → تستمر العملية
عدم تطابق ❌ → throw new Error('INVALID_VERIFICATION_CODE')
                 ← عقدة الخطأ تُرجع HTTP 400 برسالة واضحة
```

### 4.3 حماية النموذج من المحاولات المتكررة

```
المحاولة الأولى والثانية: رسالة خطأ فورية "رمز التحقق غير صحيح"
المحاولة الثالثة: قفل 5 دقائق مع عداد تنازلي بالثواني
بعد انتهاء القفل: يمكن المحاولة من جديد
```

### 6.1 مخطط الـ Workflow النهائي (v6.1.0)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    n8n Workflow — SCVA v6.1.0                       │
│                                                                     │
│  [1] Webhook — Receive Registration                                 │
│       ↓ POST /webhook/scva-member-register                          │
│                                                                     │
│  [2] Verify Invitation Code (Code JS)                               │
│       ↓ صحيح              ↓ خاطئ                                   │
│                   [Respond — Error 400]                             │
│                                                                     │
│  [3] Format & Validate Data (Code JS)                               │
│       ↓ تنظيف + تحويل + timestamp                                  │
│                                                                     │
│  [4] Build AI Prompt (Code JS)                                      │
│       ↓ يبني URL + Body للاستدعاء                                  │
│                                                                     │
│  [5] AI HTTP Request (HTTP Request node)                            │
│       ↓ يستدعي Gemini أو OpenAI                                    │
│                                                                     │
│  [6] Parse AI Response (Code JS)                                    │
│       ↓ يستخرج adminAnalysis + memberWelcome                       │
│                                                                     │
│  [7] Append to SCVA Excel (HTTP Request node)                       │
│       ↓ POST /api/public/append-excel                               │
│                                                                     │
│  [8] Is Duplicate? (IF node)                                        │
│       ↓ لا                    ↓ نعم                                 │
│                     [Respond — Duplicate]                           │
│                                                                     │
│  [9] Build Email HTML (Code JS)                                     │
│       ↓ يبني HTML للرسالتين                                        │
│                                                                     │
│  [10] Email Admin — Notification (Email node)                       │
│       ↓                                                             │
│  [11] Member has email? (IF node)                                   │
│       ↓ نعم                   ↓ لا                                 │
│  [12] Email Member             [Respond — 200 Success]              │
│  — Confirmation                                                     │
│       ↓                                                             │
│  [Respond — 200 Success]                                            │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 الاتصالات بين العقد

| من | إلى | الشرط |
|----|-----|-------|
| Webhook | Verify Invitation Code | دائماً |
| Verify Invitation Code | Format & Validate Data | رمز صحيح |
| Verify Invitation Code | Respond — Error | رمز خاطئ (error handler) |
| Format & Validate Data | Build AI Prompt | دائماً |
| Build AI Prompt | AI HTTP Request | دائماً |
| AI HTTP Request | Parse AI Response | دائماً |
| Parse AI Response | Append to SCVA Excel | دائماً |
| Append to SCVA Excel | Is Duplicate? | دائماً |

| Member has email? | Respond — 200 Success | branch 1 (لا email) |
| Email Member — Confirmation | Respond — 200 Success | دائماً |

### العقدة 1 — Webhook — Receive Registration
**النوع:** `n8n-nodes-base.webhook`
**الموضع:** بداية الـ Workflow — نقطة الدخول الوحيدة

**الوظيفة:**
يستقبل طلبات POST من نموذج تسجيل الأعضاء الخارجي. لا يعالج البيانات، فقط يستقبلها ويمررها للعقدة التالية.

**الإعدادات الجوهرية:**
```
HTTP Method  : POST
Path         : scva-member-register
Response Mode: responseNode  ← الرد يُرسَل من عقدة Respond لاحقاً
Allowed Origins: *  ← يقبل الطلبات من أي نطاق
```

**رابط الـ Webhook الكامل:**
```
https://your-n8n-instance.com/webhook/scva-member-register
```
> هذا الرابط يُنسخ ويُلصق في إعدادات التطبيق (حقل "رابط Webhook").

### العقدة 2 — Verify Invitation Code
**النوع:** `n8n-nodes-base.code` (JavaScript)
**الوظيفة:** التحقق من صحة رمز الدعوة قبل أي معالجة

**منطق العمل:**
```javascript
const body = $input.first().json.body || $input.first().json;
const submittedCode = (body.verificationCode || '').trim().toUpperCase();

// الرمز يُحقَن تلقائياً من التطبيق عند التحميل
let expectedCode = 'SCVA-2026';
try {
  const varCode = $vars.SCVA_VERIFICATION_CODE;
  if (varCode && String(varCode).trim()) {
    expectedCode = String(varCode).trim().toUpperCase();
  }
} catch (e) {}

if (!submittedCode) {
  throw new Error('MISSING_CODE: رمز التحقق مطلوب');
}
if (submittedCode !== expectedCode) {
  throw new Error('INVALID_VERIFICATION_CODE: رمز التحقق غير صحيح');
}
return [{ json: body }];
```

**نقاط مهمة:**
- الرمز يُحقَن من التطبيق داخل الكود مباشرة عند تحميل الـ Workflow (لا يحتاج متغيّر)
- أي خطأ يُطلق `throw` ينقل التنفيذ إلى عقدة `Respond — Error` تلقائياً
- الرمز case-insensitive (يقارن بعد `toUpperCase()`)

### العقدة 4 — Build AI Prompt
**النوع:** `n8n-nodes-base.code` (JavaScript)
**الوظيفة:** تحضير طلب الذكاء الاصطناعي — URL وBody وHeaders

**لماذا عقدة منفصلة؟**
n8n Code node لا يسمح بـ `fetch` ولا `require('https')` داخل الكود (مقيّد sandbox). لذا فُصلت مهمة بناء الطلب عن إرساله — الإرسال يتم عبر HTTP Request node.

**منطق العمل:**
```javascript
const AI_PROVIDER = 'gemini';       // يُحقَن من التطبيق
const AI_API_KEY  = 'AIzaSy...';   // يُحقَن من التطبيق

const hasKey = AI_API_KEY && AI_API_KEY !== '__SCVA_AI_KEY__'
               && AI_API_KEY.trim().length > 10;

if (hasKey) {
  // بناء Prompt موحّد يطلب JSON بحقلين
  const combinedPrompt = `...بيانات العضو...
  رد فقط بـ JSON صالح:
  {
    "adminAnalysis": "فقرة عربية للمسؤول",
    "memberWelcome": "رسالة ترحيب للعضو"
  }`;

  if (AI_PROVIDER === 'gemini') {
    aiUrl  = 'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=' + AI_API_KEY;
    aiBody = { contents: [{ parts: [{ text: combinedPrompt }] }] };
    aiAuthHeader = '';  // Gemini يستخدم API key في URL
  } else {
    aiUrl  = 'https://api.openai.com/v1/chat/completions';
    aiBody = { model: 'gpt-4o-mini', messages: [...], max_tokens: 500 };
    aiAuthHeader = 'Bearer ' + AI_API_KEY;  // OpenAI يستخدم Authorization header
  }
}
```

**الإخراج:** جميع حقول بيانات العضو + `aiUrl` + `aiBody` + `aiAuthHeader` + `aiSkip`

### العقدة 5 — AI HTTP Request
**النوع:** `n8n-nodes-base.httpRequest`
**الوظيفة:** إرسال طلب HTTP فعلي إلى Gemini أو OpenAI

**لماذا HTTP Request node وليس Code node؟**
Code node في n8n يعمل في بيئة sandbox مقيّدة تمنع:
- `fetch` (غير متاحة في معظم إصدارات n8n)
- `require('https')` (محجوب لأسباب أمنية)

HTTP Request node هو الطريقة الرسمية في n8n لإجراء طلبات HTTP خارجية.

**الإعدادات:**
```
Method    : POST
URL       : ={{ $json.aiUrl }}
Headers   :
  Content-Type  : application/json
  Authorization : ={{ $json.aiAuthHeader || '' }}
Body Type : json
JSON Body : ={{ $json.aiBody }}
Options   : neverError = true  (لا يوقف الـ Workflow عند فشل AI)
```

**ملاحظة مهمة:** `neverError: true` يجعل العقدة تكمل حتى عند خطأ HTTP (4xx/5xx) — إذا فشل AI يكمل الـ Workflow وتصل الرسائل بدون محتوى AI.

### العقدة 6 — Parse AI Response
**النوع:** `n8n-nodes-base.code` (JavaScript)
**الوظيفة:** استخراج `adminAnalysis` و`memberWelcome` من رد الـ API

**منطق العمل:**
```javascript
// قراءة رد HTTP
const body = httpResult.body || httpResult;

// استخراج النص حسب المزوّد
if (aiProvider === 'gemini') {
  rawText = body?.candidates?.[0]?.content?.parts?.[0]?.text || '';
} else {
  rawText = body?.choices?.[0]?.message?.content || '';
}

// تنظيف Markdown code fences إن وجدت
const clean = rawText.replace(/^```json?\n?/,'').replace(/```$/,'').trim();

// استخراج JSON من النص
const match = clean.match(/\{[\s\S]*\}/);
if (match) {
  const parsed = JSON.parse(match[0]);
  aiAnalysis = parsed.adminAnalysis || '';
  aiWelcome  = parsed.memberWelcome || '';
} else {
  // fallback: استخدام النص كاملاً كـ adminAnalysis
  aiAnalysis = rawText.trim();
}
```

**هذه العقدة تقرأ بيانات العضو من:**
```javascript
d = $('Build AI Prompt').first().json;  // البيانات الأصلية + aiSkip + aiProvider
```

**الإخراج:** جميع بيانات العضو + `aiAnalysis` + `aiWelcome` + `aiLog` (للتشخيص)

## 8. نظام الذكاء الاصطناعي

### 8.1 نظرة عامة

الذكاء الاصطناعي **اختياري** — الـ Workflow يعمل بالكامل بدونه. عند توفير مفتاح API، يُضيف قيمة ملموسة للرسائل:

| بدون AI | مع AI |
|---------|-------|
| جدول بيانات العضو فقط | جدول + تحليل احترافي للطلب |
| رسالة تأكيد عامة | رسالة ترحيب شخصية باسم الدكتور |

### 8.2 المزوّدون المدعومون

| المزوّد | النموذج | تفاصيل |
|---------|---------|--------|
| **Google Gemini** | `gemini-2.5-flash` | الافتراضي — سريع ومجاني نسبياً |
| **OpenAI** | `gpt-4o-mini` | بديل — يتطلب رصيداً |

### 8.3 بنية الطلب المُرسَل للـ AI

يُرسَل Prompt واحد لكل طلب عضوية يطلب JSON بحقلين:

```
أنت مساعد إداري للرابطة السورية لأمراض وجراحة القلب.
تلقت الرابطة طلب عضوية بالبيانات التالية:
- الاسم: ابراهيم الصيداوي (ibrahim sidawi)
- التخصص: Cardiac Surgery
- نوع العضوية: Original Member
- المدينة: damascus
- رقم ESC: غير موجود
- بريد إلكتروني: موجود
- هاتف: موجود

رد فقط بـ JSON صالح (بدون markdown):
{
  "adminAnalysis": "فقرة عربية 3-4 جمل للمسؤول",
  "memberWelcome": "رسالة ترحيب للعضو بلغته"
}
```

### 8.4 فلسفة التصميم — لماذا Prompt واحد؟

طلب واحد بدلاً من طلبين:
- يوفّر تكلفة API (50% أقل)
- يُقلّل وقت الاستجابة
- يُبسّط معالجة الأخطاء

### 8.5 معالجة الرد

## 11. آلية حقن الإعدادات عند تحميل الـ Workflow

عند الضغط على "تحميل ملف Workflow" في صفحة الإعدادات، يُنفّذ السيرفر الخطوات التالية:

```javascript
// server/routes.ts — GET /api/admin/workflow

const settings = await storage.getFormSettings();
const workflow  = JSON.parse(readFileSync(workflowPath, 'utf-8'));

for (const node of workflow.nodes) {

  // 1. عقدة التحقق — حقن رمز الدعوة في الكود مباشرة
  if (node.id === 'verify-code') {
    node.parameters.jsCode = node.parameters.jsCode.replace(
      /const expectedCode = '.*?';/,
      `const expectedCode = '${settings.verificationCode}';`
    );
  }

  // 2. عقدة Email Admin — حقن بريد المسؤول
  if (node.id === 'email-admin') {
    node.parameters.toEmail   = settings.notificationEmail;
    node.parameters.fromEmail = settings.notificationEmail;
  }

  // 3. عقدة Email Member — حقن بريد المرسِل
  if (node.id === 'email-member') {
    node.parameters.fromEmail = settings.notificationEmail;
  }

  // 4. عقدة Build AI Prompt — حقن مزوّد AI ومفتاحه
  if (node.id === 'build-ai-prompt') {
    node.parameters.jsCode = node.parameters.jsCode
      .replace("'__SCVA_AI_PROVIDER__'", `'${settings.aiProvider}'`)
      .replace("'__SCVA_AI_KEY__'",      `'${settings.aiApiKey}'`);
  }

  // 5. عقدة Append Excel HTTP — حقن رابط التطبيق ومفتاح API
  if (node.id === 'append-excel-http') {
    node.parameters.url = `${appUrl}/api/public/append-excel`;
    // حقن Bearer token في header Authorization
  }
}

res.json(workflow);  // تحميل الملف المحدَّث مباشرة
```

**النتيجة:** الملف المُحمَّل يحتوي على جميع الإعدادات الحقيقية — لا حاجة لأي إعداد يدوي في n8n ما عدا SMTP.

```
                            200              │Email Member│──► بريد العضو
                                             └─────┬──────┘
                                                   │
                                             Respond 200
```

## 14. الأخطاء الشائعة وحلولها

### خطأ: `fetch is not defined`
**السبب:** n8n Code node لا يدعم `fetch` في بيئة sandbox المقيّدة.
**الحل:** استخدام HTTP Request node منفصل للطلبات الخارجية (الحل المُطبَّق في v6.0).

### خطأ: `Module 'https' is disallowed`
**السبب:** n8n Code node يمنع `require('https')` لأسباب أمنية.
**الحل:** HTTP Request node هو الطريقة الصحيحة لجميع الطلبات الخارجية في n8n.

### خطأ: `Invalid JSON payload received`
**السبب:** استخدام `specifyBody: "string"` مع `JSON.stringify()` يُشكّل الـ body كـ string داخل wrapper بدلاً من JSON حقيقي.
**الحل:** استخدام `specifyBody: "json"` مع `jsonBody: ={{ $json.aiBody }}` (الحل في v6.1).

### مشكلة: رسالة العضو لا تصل
**السبب:** بعد تنفيذ `Email Admin`، يُصبح `$json` ناتج الإرسال وليس بيانات العضو. شرط `Member has email?` يتحقق من `$json.memberEmail` فيجد `undefined`.
**الحل:** الشرط والعقدة يقرآن من `$('Build Email HTML').first().json.memberEmail` مباشرة (الحل في v3.8).

### مشكلة: AI لا يعمل رغم صحة المفتاح
**الأسباب المحتملة:**
1. الـ Workflow المستورد في n8n يحتوي على placeholders (`__SCVA_AI_KEY__`) لأنه لم يُحمَّل من التطبيق
2. نموذج Gemini المحدّد غير متاح (جرّب `gemini-2.5-flash`)
3. مفتاح OpenAI منتهي الصلاحية أو تجاوز الحصة

**التشخيص:** انظر حقل `aiLog` في Output عقدة `Parse AI Response`:
```
skip=false       ← المفتاح موجود ويعمل
httpStatus=200   ← AI أجاب
rawTextLen=423   ← رد غير فارغ
parsed OK        ← تم تحليل JSON بنجاح
```

### مشكلة: `hasKey=false` في aiLog
**السبب:** الـ Workflow استُورد مباشرة من الملف بدون تحميله من التطبيق — المفتاح لا يزال placeholder.
**الحل:** التطبيق → الإعدادات → **تحميل ملف Workflow** → استورده في n8n بدلاً من القديم.

## 15. خطوات التشغيل الكاملة

### في التطبيق (مرة واحدة قبل الإطلاق):

1. صفحة **الإعدادات** → قسم "إعدادات نموذج التسجيل الخارجي"
2. عيّن **رمز الدعوة** (مثلاً: `SCVA-2026`)
3. أدخل **بريد الإشعارات** (بريد المسؤول)
4. *(اختياري)* قسم "إعدادات الذكاء الاصطناعي" → اختر المزوّد → أدخل المفتاح → اضغط **اختبار**
5. اضغط **تحميل ملف Workflow** — احفظ الملف

### في n8n:

1. **Import** → اختر `scva-member-workflow.json` المُحمَّل
2. **Credentials** → **Add** → نوع: `SMTP` → أدخل بيانات البريد
3. افتح عقدة `Email Admin — Notification` → اختر الـ Credential
4. افتح عقدة `Email Member — Confirmation` → اختر الـ Credential
5. اضغط **Activate** لتفعيل الـ Workflow
6. انسخ رابط Webhook (ظاهر في عقدة Webhook) وألصقه في إعدادات التطبيق

### للأعضاء:

1. يستلمون رابط النموذج `https://your-app.replit.app/form` + رمز الدعوة
2. يفتحون الرابط في أي متصفح
3. يُدخلون رمز الدعوة في الخطوة الأولى
4. يعبئون بياناتهم ويضغطون إرسال
5. ✅ تظهر صفحة التأكيد — البيانات حُفظت والإشعارات أُرسلت

### التحقق من عمل النظام:

1. أرسل طلباً تجريبياً عبر النموذج
2. n8n: اضغط على التنفيذ الأخير واسترجع نتائج كل عقدة
3. تحقق من وصول إيميل المسؤول
4. تحقق من وصول إيميل العضو (إذا أدخلت بريداً)
5. التطبيق → الإعدادات → **تحميل ملف الإكسل** وتحقق من الصف الجديد

## ملاحظات للاستخدام في مشاريع أخرى

هذا النظام قابل للتطبيق على أي منظمة تحتاج نموذج تسجيل خارجي مع إشعارات وحفظ بيانات. المبادئ المُطبَّقة:

**1. عزل المنطق في Code nodes والاتصالات في HTTP Request nodes**
لا تحاول الاتصال بـ APIs من داخل Code node في n8n — استخدم HTTP Request node دائماً.

**2. بناء HTML المعقّد في Code node**
تعبيرات n8n في Email node محدودة — ابنِ HTML كاملاً في Code واستخدم مرجعاً بسيطاً في Email.

**3. الرجوع للعقدة المصدر بعد Email node**
بعد Email node، `$json` يصبح نتيجة الإرسال. استخدم دائماً `$('اسم-العقدة').first().json` للرجوع للبيانات الأصلية.

**4. حقن الإعدادات في الـ Workflow عند التحميل**
لا تطلب من المستخدم إعداد متغيّرات في n8n يدوياً — احقن كل شيء في الملف عند التحميل من التطبيق.

**5. جعل AI اختيارياً بـ `neverError: true`**
الذكاء الاصطناعي يُضيف قيمة لكنه لا يُوقف العمل عند فشله. استخدم `neverError` ومعالجة fallback.
